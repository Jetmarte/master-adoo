# Categorización Clásica

## 📌 Definición Formal

> **"Todas las entidades que tienen una determinada propiedad o conjunto de propiedades en común forman una categoría. Estas propiedades son necesarias y suficientes para definir la categoría."** — Grady Booch

Una **categoría clásica** es un conjunto de objetos que comparten características definidas de manera **clara, precisa y exhaustiva**.

---

## 🎯 Características Principales

### 1. **Límites Bien Definidos**
Una entidad pertenece o NO pertenece a una categoría. No hay zona gris.

```
Pertenece a "Aves"    ✅ o ❌ No pertenece
              ↓                    ↓
            Sí                    No
       (binario)              (binario)
```

### 2. **Propiedades Necesarias y Suficientes**
```
PROPIEDADES NECESARIAS = Debe tener TODAS
PROPIEDADES SUFICIENTES = Con solo éstas basta
```

**Ejemplo: Categoría AVES**
```
Propiedades NECESARIAS Y SUFICIENTES:
├─ Tener plumas
├─ Tener pico
├─ Tener alas
└─ Poner huevos

Si tiene TODAS → Es AVE
Si le falta UNA → NO es AVE
```

### 3. **Lógica Booleana**
```
Pertenencia = AND (Y)
├─ Tiene plumas AND
├─ Tiene pico AND
├─ Tiene alas AND
└─ Pone huevos
    ↓
    RESULTADO: PERTENECE o NO PERTENECE
```

## 💡 Ejemplo Clásico: Las Aves

### Definición Clásica (Ideal)
```
CATEGORÍA: Aves
├─ Propiedad 1: Tener plumas
├─ Propiedad 2: Tener pico
├─ Propiedad 3: Tener alas
└─ Propiedad 4: Poner huevos

MIEMBROS PERFECTOS:
├─ Águila ✅ (tiene todo)
├─ Paloma ✅ (tiene todo)
├─ Loro ✅ (tiene todo)
└─ Gallina ✅ (tiene todo)
```

### Problema: Excepciones

> **"Las categorías naturales tienden a ser un poco incómodas: la mayoría de los pájaros vuelan, pero algunos no lo hacen; las sillas pueden consistir de madera, plástico o metal y pueden tener casi cualquier número de patas..."** — Bart Kosko

```
PROBLEMAS CON LA DEFINICIÓN CLÁSICA:

Pingüino:
├─ Tiene plumas ✅
├─ Tiene pico ✅
├─ Tiene alas ✅
├─ Pone huevos ✅
└─ Pero NO VUELA ❌

¿Es AVE o NO?
Según definición: ✅ SÍ (tiene todas las propiedades)
Según intuición: ¿? (NO vuela)
```

## 🔍 Análisis Detallado

### Categorización Clásica FUNCIONA en:

```
✅ Categorías artificiales:
   ├─ Archivo
   ├─ Clase (en OOP)
   ├─ Interfaz
   └─ Protocolo

✅ Conceptos matemáticos:
   ├─ Números pares
   ├─ Triángulos
   ├─ Conjuntos
   └─ Funciones

✅ Definiciones legales:
   ├─ Mayor de edad
   ├─ Casado
   ├─ Ciudadano
   └─ Contratante
```

### Categorización Clásica FALLA en:

```
❌ Categorías naturales:
   ├─ Aves (pingüino no vuela)
   ├─ Peces (delfín no es pez)
   ├─ Mamíferos (ornitorrinco pone huevos)
   └─ Muebles (cajón ¿es silla?)

❌ Conceptos difusos:
   ├─ Rojo (¿dónde termina el rojo?)
   ├─ Alto (¿cuánto es "alto"?)
   ├─ Joven (¿a qué edad?)
   └─ Grande (¿qué tamaño?)

❌ Dominios complejos:
   ├─ Biología
   ├─ Sociología
   ├─ Psicología
   └─ Ecología
```

## 🎓 Ejemplo en OOP (Programación)

### Definición Clásica: Clase Animal

```typescript
class Animal {
  // Propiedades necesarias y suficientes
  nombre: string;
  edad: number;
  especie: string;

  // Métodos
  moverse() { }
  comer() { }
  respirar() { }
}
```

### Derivación: Clase Aves

```typescript
class Aves extends Animal {
  // Propiedades adicionales
  tienePlumas: boolean = true;
  tienePico: boolean = true;
  tienAlas: boolean = true;
  poneHuevos: boolean = true;

  // Métodos
  volar() { }
  cantar() { }
}
```

### El Problema del Pingüino

```typescript
class Pinguino extends Aves {
  // Hereda todas las propiedades de Aves
  tienePlumas = true;      ✅
  tienePico = true;        ✅
  tienAlas = true;         ✅
  poneHuevos = true;       ✅

  // PERO no implementa correctamente:
  volar() {
    throw new Error("Los pingüinos no vuelan");
  }
}
```

**Problema:** El método `volar()` de la clase Aves es violado por Pingüino.
Esto viola el **Principio de Sustitución de Liskov**.

## 🚫 Problemas de la Categorización Clásica

### 1. **Excepciones Abundantes**
```
Regla: "Los pájaros vuelan"
Excepciones: Pingüino, avestruz, kiwi, emú...

¿Qué hacer?
├─ Incluir la excepción → "Los pájaros vuelan, excepto..."
├─ Cambiar la definición → Pero falla en otros casos
└─ Aceptar que la categoría es imperfecta
```

### 2. **Límites Difusos**
```
¿Dónde está el límite?

Categoría: ALTO
├─ 1.50m ❌ Bajo
├─ 1.70m ❓ Medio
├─ 1.90m ✅ Alto
└─ ¿Cuál es el valor exacto?
```

### 3. **Propiedades No Exhaustivas**
```
Categoría: SILLA
├─ Tiene 4 patas
├─ Tiene respaldo
├─ Está hecha de madera

Problemas:
├─ ¿Una silla de 3 patas es silla?
├─ ¿Una silla sin respaldo es silla?
├─ ¿Una silla de plástico es silla?
└─ Respuesta: DEPENDE
```

### 4. **Falta de Gradualidad**
```
Clasificación clásica: Todo o nada
├─ Es AVE ✅ o NO es AVE ❌
├─ Es MUEBLE ✅ o NO es MUEBLE ❌
└─ Sin punto intermedio

Realidad: Hay grados
├─ Pingüino es "casi" un ave (90%)
├─ Un objeto es "algo" mueble (70%)
└─ Hay ejemplares más o menos típicos
```

## 💻 Aplicación en Ingeniería de Software

### Sistema de Clasificación Clásico

```typescript
// Interfaz con propiedades necesarias y suficientes
interface Animal {
  nombre: string;
  respirar(): void;
  moverse(): void;
  comer(): void;
}

interface Ave extends Animal {
  tienePlumas: true;      // Necesaria
  tienePico: true;        // Necesaria
  puedeVolar: true;       // Necesaria
  volar(): void;          // Necesaria
}

class Aguila implements Ave {
  // Cumple TODAS las propiedades
  tienePlumas = true;
  tienePico = true;
  puedeVolar = true;

  volar() { console.log("Volando..."); }
}

class Pinguino implements Ave {  // ❌ PROBLEMA
  // Cumple CASI todas las propiedades
  tienePlumas = true;
  tienePico = true;
  puedeVolar = false;      // ❌ Viola el contrato

  volar() {
    throw new Error("No puedo volar"); // ❌ Viola Liskov
  }
}
```

### Solución: Jerarquía Revisada

```typescript
// Separar el concepto de volar
interface Animal {
  nombre: string;
  respirar(): void;
  moverse(): void;
}

interface Ave extends Animal {
  tienePlumas: true;
  tienePico: true;
  poneHuevos: true;
  // NO incluir volar (no es esencial)
}

interface AveVoladora extends Ave {
  puedeVolar: true;
  volar(): void;
}

class Aguila implements AveVoladora {
  // Implementa completo
  puedeVolar = true;
  volar() { }
}

class Pinguino implements Ave {
  // Implementa solo Ave, no AveVoladora
  // ✅ No hace promesas que no cumple
}
```

## 🎯 Cuándo Usar Categorización Clásica

### ✅ USA CATEGORIZACIÓN CLÁSICA cuando:

1. **Categorías artificiales**
   - Clases de programación
   - Interfaces
   - Protocolos
   - Especificaciones

2. **Dominios bien definidos**
   - Matemáticas
   - Derecho
   - Normativas
   - Estándares

3. **Necesitas precisión absoluta**
   - Sistemas críticos
   - Seguridad
   - Validaciones

### ❌ NO USES CATEGORIZACIÓN CLÁSICA cuando:

1. **Categorías naturales**
   - Biología
   - Ecología
   - Sociología

2. **Conceptos vagos**
   - Colores
   - Tamaños
   - Edades

3. **Dominios complejos**
   - Comportamiento humano
   - Fenómenos naturales
   - Sistemas sociales

## 🎓 Conclusión

La **Categorización Clásica** es un enfoque **riguroso y preciso**, pero **inflexible** ante la realidad. Funciona perfectamente en dominios artificiales y bien definidos, pero falla cuando hay excepciones naturales.

El **Pingüino** es el ejemplo más icónico: cumple todas las propiedades de un ave EXCEPTO que no vuela. Esto muestra que las categorías naturales necesitan un enfoque más flexible: la **Teoría de Prototipos**.
