Sinónimos: Lazy Class [Smell Code (Refactoring) - Martin Fowler]

 Justificación:

-  Cada clase que se crea cuesta dinero para mantenerla y entenderla.
-  Una clase que no está haciendo lo suficiente para justificar el coste por sí mismo debería ser eliminada.
-  A menudo, esto podría ser una clase que paga por su bagaje y se ha reducido con la refactorización.
-  O podría ser una clase que fue añadida a causa de los cambios que estaban previstos, pero nunca llegaron.

 Solución:

-  De cualquier manera, dejar que la clase muera con dignidad asignando su escasa responsabilidad a otra clase
-  Si hay subclases que no están haciendo lo suficiente, trate de contraer la jerarquía.


 **“code smells”** (malos olores en el código) relacionados con **Lazy Classes** (clases perezosas) que se describen en _Refactoring_ de Martin Fowler. Te lo explico en ese contexto:

---

## 🚨 Código sucio: Lazy Class (Clase Perezosa)

Una **Lazy Class** es una clase que **no hace lo suficiente como para justificar su existencia**.  
Es decir, ocupa espacio en el diseño, añade complejidad, pero apenas tiene lógica o responsabilidad real.

### 🧩 Características de una Lazy Class:

- Tiene muy pocos métodos.
    
- Sus métodos son triviales (getters/setters sin más).
    
- Delegan casi todo a otra clase.
    
- Su existencia rompe el principio de _“no más abstracciones de las necesarias”_.
    

Ejemplo típico en Java/Python (muy simplificado):

```python
class Direccion:
    def __init__(self, calle, ciudad):
        self.calle = calle
        self.ciudad = ciudad
```

Esta clase **no hace nada útil** aparte de almacenar datos. Si no hay comportamiento adicional relacionado con la dirección, es “perezosa” y podría reemplazarse por un simple diccionario o integrarse en otra clase.

---

## 🛠️ Cómo refactorizar una Lazy Class

1. **Inline Class (Integrar Clase)**  
    Si la clase solo se usa en un lugar, mover sus atributos y métodos directamente a la clase que la usa.
    
2. **Collapse Hierarchy (Colapsar Jerarquía)**  
    Si es parte de una jerarquía pero no añade valor, fusiónala con la superclase o subclase.
    
3. **Eliminar directamente**  
    Si no cumple ninguna función.
    

---

## ✅ Ejemplo de Refactorización

### Antes (Lazy Class):

```python
class Direccion:
    def __init__(self, calle, ciudad):
        self.calle = calle
        self.ciudad = ciudad

class Cliente:
    def __init__(self, nombre, calle, ciudad):
        self.nombre = nombre
        self.direccion = Direccion(calle, ciudad)

    def mostrar_info(self):
        return f"{self.nombre}, {self.direccion.calle}, {self.direccion.ciudad}"
```

### Después (Clase Eliminada):

```python
class Cliente:
    def __init__(self, nombre, calle, ciudad):
        self.nombre = nombre
        self.calle = calle
        self.ciudad = ciudad

    def mostrar_info(self):
        return f"{self.nombre}, {self.calle}, {self.ciudad}"
```

---

👉 En resumen:  
El **código sucio por clases perezosas** aparece cuando tenemos clases que no aportan valor y solo complican el diseño. La solución es **integrarlas, fusionarlas o eliminarlas** para mantener el sistema más claro y simple.
