Sinónimos:

-  Incomplete Library Class [Smell Code (Refactoring) – Martin Fowler]

 Justificación:

-  Los desarrolladores de clases de biblioteca son raramente omniscientes. No los culpamos por eso, después de todo, rara vez podemos imaginar un diseño hasta su mayoría que hemos construido, así que los desarrolladores de la biblioteca tienen un trabajo muy duro.
- El problema es que a menudo es de mala educación, y por lo general imposible, modificar una clase de biblioteca para hacer algo que te gustaría que hiciera.

 Solúción:

-  Crea una clase con los métodos extra adecuados a tus necesidades

## 📌 ¿Qué es el “Incomplete Library Class”?

Es un **code smell** descrito por Martin Fowler que ocurre cuando:

- Una **clase de una librería externa** no tiene todas las funciones que necesitas.
    
- No puedes modificar la clase porque **no es tuya** (es de la librería).
    
- Terminas escribiendo **código repetido, improvisado o parcheado** para suplir lo que falta.
    

Esto lleva a un diseño **sucio**, porque tu código depende de huecos en la librería.

---

## ❌ Código sucio (usando directamente la librería incompleta)

La clase `File` de Java no tiene un método para contar líneas de un archivo.  
Entonces muchos devs escriben este bloque **cada vez que lo necesitan** 👇

```java
import java.io.*;

public class ContadorLineas {
    public static void main(String[] args) throws IOException {
        File archivo = new File("datos.txt");

        int lineas = 0;
        BufferedReader br = new BufferedReader(new FileReader(archivo));
        while (br.readLine() != null) {
            lineas++;
        }
        br.close();

        System.out.println("Total de líneas: " + lineas);
    }
}
```

👉 Problemas:

- Lógica duplicada cada vez que quieras contar líneas.
    
- Si mañana decides optimizar la lectura, tendrás que cambiarlo en todos lados.
    

---

## ✅ Código refactorizado (clase utilitaria que extiende la librería)

Se crea una clase **`FileUtils`** para centralizar la funcionalidad que falta:

```java
import java.io.*;

public class FileUtils {

    // Método que amplía la funcionalidad de File
    public static int countLines(File archivo) throws IOException {
        int lineas = 0;
        try (BufferedReader br = new BufferedReader(new FileReader(archivo))) {
            while (br.readLine() != null) {
                lineas++;
            }
        }
        return lineas;
    }
}
```

Uso:

```java
import java.io.File;
import java.io.IOException;

public class Demo {
    public static void main(String[] args) throws IOException {
        File archivo = new File("datos.txt");
        int total = FileUtils.countLines(archivo);
        System.out.println("Total de líneas: " + total);
    }
}
```

👉 Beneficios:

- Código limpio y reutilizable.
    
- Si necesitas mejorar la lógica, solo editas `FileUtils`.
    
- Evitas duplicación en todo el proyecto.
    

---

📌 Otro caso común en Java es con **`Date` y `Calendar`**, que son limitados.  
En lugar de repetir lógica complicada, se crean **utilidades propias o se usan librerías como `java.time` (Java 8+) o Joda-Time**.
