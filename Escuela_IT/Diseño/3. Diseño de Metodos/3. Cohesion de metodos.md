**Sinónimos**:

 La funciones deberían hacer una sola cosa (Functions Should Do One 
Thing ) [Smell Code (Refactoring); Martin Fowler]

 **Justificación**:

▫ A menudo se intenta crear funciones que tienen multiples secciones  que realizan una serie de operaciones. Dicho de otra manera, la  relacion entre las líneas de la implantación del método no son  cohesivas porque persiguen distintos objetivos 
▫ Producen un acoplamiento temporal e imposibilitan su reusabilidad. 
	• *Método que calcula la longitude de un Interval y muestra el resultado por pantalla. Cuando solo se necesita el cálculo, no es reutilizable*

 **Solución**:
▫ Deberían ser convertidas varias funciones pequeñas que hacen una sola cosa 


---

## 🔹 ¿Qué es Cohesión?

En ingeniería de software, la **cohesión** mide **qué tan relacionadas están las responsabilidades internas de una unidad de código** (un método, clase o módulo).

- **Alta cohesión** → El método o clase hace **una sola cosa**, bien definida, y todas sus partes están relacionadas entre sí.
    
- **Baja cohesión** → El método o clase hace cosas **muy diferentes**, mezclando responsabilidades.
    

👉 Lo ideal es **alta cohesión**, porque el código se vuelve **más fácil de entender, mantener y probar**.

---

## 🔹 Cohesión a nivel de **métodos**

Un **método con cohesión alta**:

- Hace **una sola tarea clara**.
    
- Todas sus instrucciones están enfocadas en ese propósito.
    

Un **método con cohesión baja**:

- Hace muchas cosas no relacionadas.
    
- Se encarga de lógica de negocio, validación, impresión en pantalla, acceso a base de datos, etc., todo mezclado.
    

---

## 🧩 Ejemplo en Java (baja cohesión)

```java
public void procesarPedido(Pedido pedido) {
    // 1. Validar datos
    if (pedido.getCliente() == null) {
        throw new IllegalArgumentException("El pedido no tiene cliente");
    }

    // 2. Calcular total
    double total = 0;
    for (Producto p : pedido.getProductos()) {
        total += p.getPrecio();
    }

    // 3. Guardar en la base de datos
    System.out.println("Guardando pedido en la base de datos...");

    // 4. Enviar correo de confirmación
    System.out.println("Enviando email al cliente...");
}
```

### ❌ Problemas:

- El método valida, calcula, guarda en BD y envía correo → **baja cohesión**.
    
- Si cambia la lógica de email o BD, este método se verá afectado innecesariamente.
    

---

## ✅ Refactorización (alta cohesión)

Separando responsabilidades en métodos más cohesivos:

```java
public void procesarPedido(Pedido pedido) {
    validarPedido(pedido);
    double total = calcularTotal(pedido);
    guardarPedido(pedido, total);
    enviarConfirmacion(pedido);
}

private void validarPedido(Pedido pedido) {
    if (pedido.getCliente() == null) {
        throw new IllegalArgumentException("El pedido no tiene cliente");
    }
}

private double calcularTotal(Pedido pedido) {
    double total = 0;
    for (Producto p : pedido.getProductos()) {
        total += p.getPrecio();
    }
    return total;
}

private void guardarPedido(Pedido pedido, double total) {
    System.out.println("Guardando pedido en la base de datos con total: " + total);
}

private void enviarConfirmacion(Pedido pedido) {
    System.out.println("Enviando email al cliente " + pedido.getCliente().getEmail());
}
```

### ✅ Ventajas:

- Cada método tiene **alta cohesión** (hace solo una cosa).
    
- El método `procesarPedido()` ahora se entiende **como un flujo de pasos claros**.
    
- Facilita **mantenimiento y pruebas unitarias**.
    

---

## 🎯 Resumen

- **Cohesión de métodos** = grado en que todas las instrucciones de un método están enfocadas en una sola tarea.
    
- **Alta cohesión** → métodos cortos, claros y con una única responsabilidad.
    
- **Baja cohesión** → métodos largos, mezclados y difíciles de mantener.
