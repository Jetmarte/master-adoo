## 🔹 Principio de Menor Compromiso (Principle of Least Commitment)

👉 También llamado **Principio de la decisión tardía** (_Principle of Least Commitment_).

### 📖 Definición

Cuando diseñamos un sistema, debemos **posponer decisiones de diseño** hasta que tengamos la información suficiente para tomarlas de forma correcta.

- Evita **comprometerse demasiado pronto** con una tecnología, formato, arquitectura o implementación.
    
- Nos da **flexibilidad para adaptarnos a cambios futuros**.
    

### ✅ Ejemplo

En vez de acoplarte a una **base de datos específica** desde el inicio:

❌ Mal diseño (compromiso temprano):

```java
public class ClienteRepository {
    private Connection conexionMySQL;

    public ClienteRepository() {
        // Conexión fija a MySQL
        this.conexionMySQL = DriverManager.getConnection("jdbc:mysql://...");
    }
}
```

✔️ Mejor diseño (menor compromiso):

```java
public interface ClienteRepository {
    void guardar(Cliente cliente);
}

public class ClienteRepositorySQL implements ClienteRepository {
    public void guardar(Cliente cliente) {
        // Guardar en SQL
    }
}

public class ClienteRepositoryMongo implements ClienteRepository {
    public void guardar(Cliente cliente) {
        // Guardar en MongoDB
    }
}
```

👉 Aquí no me comprometo a MySQL desde el inicio.  
Puedo cambiar la implementación sin reventar el sistema.

## 🔹 Principio de Mínima Sorpresa (Principle of Least Astonishment)

👉 También llamado **Principio de la menor sorpresa**.

### 📖 Definición

El sistema debe **comportarse de la forma más natural y esperada para el usuario o desarrollador**.

- Si algo sorprende o confunde, el diseño es malo.
    
- La interfaz (de usuario o de programación) debe ser **consistente, clara y predecible**.
    

### ✅ Ejemplo

Supongamos que tenemos un método que devuelve el tamaño de una lista:

❌ Mal diseño (sorprende al usuario):

```java
List<String> lista = Arrays.asList("A", "B", "C");
System.out.println(lista.size()); // devuelve 3
System.out.println(lista.length()); // lanza excepción 🤯
```

✔️ Buen diseño (mínima sorpresa):

```java
System.out.println(lista.size());   // siempre devuelve la cantidad
```

Otro caso:  
Si tienes un botón **“Eliminar”**, el usuario espera que **borre el elemento**, no que lo **desactive temporalmente** sin avisar.

---

## 🎯 Resumen

- **Menor Compromiso** → Diseña de forma que **pospongas decisiones** y mantengas la flexibilidad.
    
- **Mínima Sorpresa** → Haz que el sistema se comporte de manera **natural y predecible**, evitando resultados inesperados.
