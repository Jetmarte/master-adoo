### ¿Por qué es importante el formato de código?
 
El formato del código no es solo una cuestión de estética, sino una herramienta fundamental para la **comunicación efectiva** en el desarrollo de software. Un código bien formateado es:

*   **Más fácil de leer y entender:** Permite a otros desarrolladores (y a tu yo futuro) comprender rápidamente la lógica y la estructura.
*   **Más fácil de mantener:** Reduce la probabilidad de introducir errores al modificar o extender el código.
*   **Facilita la colaboración:** Mejora el trabajo en equipo al establecer un lenguaje visual común.

### Principios Clave para un Código Limpio:

Aquí te presento las directrices esenciales para lograr un formato de código profesional y legible:

#### 1. Organización Lógica: ¡Todo en su lugar!

*   **Separación de bloques:** Usa una línea en blanco para separar grupos lógicos de código. Esto es especialmente útil entre atributos y métodos, o entre diferentes métodos dentro de una clase.
*   **Declaración de atributos:** Declara las variables de instancia (atributos) al principio de la clase. Así, son fáciles de identificar.
*   **Proximidad de funciones:** Las funciones que se llaman entre sí deben estar cerca. La convención es poner primero la función que llama y luego la que es llamada.
*   **Agrupación por funcionalidad:** Mantén juntas las funciones que realizan tareas similares. Esto crea bloques de código coherentes y fáciles de seguir.

#### 2. Proximidad y Alcance de Variables: ¡Menos es más!

*   **Declaración temprana:** Declara las variables lo más cerca posible de su primer uso. Esto ayuda a entender su propósito y cuánto tiempo estarán activas (su alcance) de forma inmediata.

#### 3. Longitud de Línea y Espacio en Blanco: ¡Respiración para tu código!

*   **Líneas cortas:** Los programadores suelen preferir líneas de código no muy largas. Un ideal es alrededor de 40 caracteres, con un máximo recomendado entre 80 y 120 caracteres.
*   **Espacio en blanco horizontal:** Úsalo estratégicamente para:
    *   **Asociar:** Unir elementos fuertemente relacionados (ej. `variable = valor`).
    *   **Separar:** Distanciar elementos menos relacionados.
    *   **Enfatizar:** Clarificar la precedencia de operadores en expresiones complejas.

#### 4. Jerarquía y Sangría: ¡La estructura visible!

*   **El código tiene niveles:** Piensa en la jerarquía: archivo, clase, método, bloque dentro de un método, etc. Cada nivel es un "ámbito" donde se definen nombres.
*   **La sangría es clave:** Utiliza la sangría (indentación) de forma consistente para reflejar esta jerarquía. Una sangría correcta hace que la estructura del código sea obvia a simple vista.

### Errores Comunes a Evitar:

*   **Tabuladores para alinear:** Evita usar tabuladores para alinear tipos y variables en columnas. Esto puede causar problemas visuales si los nombres de los tipos tienen longitudes diferentes.
*   **Romper la sangría:** Nunca ignores las reglas de sangría, por cortas que sean las líneas. La consistencia es fundamental.

### Máximas para recordar:

*   "Los conceptos que están estrechamente relacionados deben mantenerse verticalmente cercanos." - Robert C. Martin
*   **Consistencia en equipo:** Un equipo debe acordar un único estilo de formato y todos deben seguirlo rigurosamente.
