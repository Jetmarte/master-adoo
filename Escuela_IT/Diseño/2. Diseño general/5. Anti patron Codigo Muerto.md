Sinónimos:

▫ Antipatrón “Dead Code”
▫ Flujo de lava “Lava Flow”

 Justificación:

▫ Según el código muerto se anquilosa y se endurecen, rápidamente se hace imposible documentar el código o entender suficientemente su  arquitectura para hacer mejoras.

▫ Si no se elimina el código muerto, puede continuar proliferando  según se reutiliza código en otras áreas 

▫ Puede haber crecimiento exponencial según los sucesivos  desarrolladores, demasiado apremiados o intimidados por analizar  los códigos originales, seguirán produciendo nuevos flujos secundarios en su intento de evitar los originales.

Síntomas:

▫ Fragmentos de código injustificables en el sistema: clases, funciones o segmentos de código complejo no documentado con aspecto importante pero que no están relacionados con el sistema 
▫ Bloques enteros de código comentado sin explicación o documentación
▫ Interfaces no usadas, inexplicables u obsoletas
▫ Montones de áreas de código con comentarios: “proceso de cambio”, “para ser reemplazado”, ..


---

## 🚨 ¿Qué es el _Dead Code_?

Se llama **código muerto** a cualquier fragmento de programa que:

- **Nunca se ejecuta**, porque no hay forma de alcanzarlo.
    
- **Ya no se usa**, porque nadie lo llama.
    
- **Sobró de una versión anterior**, pero quedó olvidado en el código.
    

👉 Aunque no afecte directamente la ejecución, **aumenta la complejidad innecesaria** y confunde a otros desarrolladores.

---

## 🧩 Ejemplo en Java

### Ejemplo 1: Método nunca usado

```java
public class Cliente {
    private String nombre;

    public Cliente(String nombre) {
        this.nombre = nombre;
    }

    public String getNombre() {
        return nombre;
    }

    // ❌ Método muerto (nadie lo llama en el sistema)
    public String getNombreEnMayusculas() {
        return nombre.toUpperCase();
    }
}
```

Aquí `getNombreEnMayusculas()` nunca es invocado → **código muerto**.

---

### Ejemplo 2: Bloque inalcanzable

```java
public int dividir(int a, int b) {
    if (b == 0) {
        return 0;
    } else {
        return a / b;
    }
    // ❌ Código muerto (nunca se ejecutará)
    System.out.println("Esta línea es inalcanzable");
}
```

La última línea después del `return` es **código muerto**, jamás se ejecuta.

---

### Ejemplo 3: Variables sin uso

```java
public void procesar() {
    int x = 10; // ❌ Variable muerta, nunca se usa
    System.out.println("Procesando...");
}
```

---

## ✅ Cómo eliminar el código muerto

1. **Borrar métodos, clases o variables no usadas.**  
    → El compilador moderno (Java, C#, etc.) puede advertir sobre esto.
    
2. **Refactorizar condiciones.**  
    → Si un `if` siempre es verdadero/falso, elimina la rama muerta.
    
3. **Eliminar código comentado.**  
    → El control de versiones (Git) ya guarda el historial, no necesitas tenerlo “por si acaso” en comentarios.
    

---

## 🎯 Resumen

- El **código muerto** no se ejecuta ni aporta valor.
    
- Aumenta la complejidad, confunde y hace más difícil mantener el sistema.
    
- La mejor práctica es **eliminarlo sin miedo** (porque el control de versiones guarda el historial).
