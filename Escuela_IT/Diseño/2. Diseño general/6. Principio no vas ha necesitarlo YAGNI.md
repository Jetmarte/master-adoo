**Sinónimos**:

▫ **YAGNI** (You aren't going to need it o You ain't gonna need it);

▫ Generalidad Especulativa (Speculative Generality - Smell Code/Refactoring)

YAGNI esta en contra posicion a interfaz suficiente, completa y primitiva.

 **Justificación**:

▫ Siempre se implementan cosas cuando realmente se necesitan, no  cuando se prevén que se necesiten. Por tanto, no se debe agregar  funcionalidad hasta que se considere estrictamente necesario.
▫ Las características innecesarias son inconveniente por:
	• El tiempo gastado se toma para la adición, la prueba o la mejora de funcionalidad innecesaria. Y posteriormente, las nuevas características deben depurarse, documentarse y mantenerse.
	• Conduce a la hinchazón de código y el software se hace más grande y más complicado. Añadir nuevas características puede sugerir otras nuevascaracterísticas. Si estas nuevas funciones se  implementan así, esto podría resultar en un efecto bola de nieve

Violaciones:

▫ Inconveniente por:
	• Hasta que la característica es realmente necesaria, es difícil definir completamente lo que debe hacer y probarla. Si la nueva  característica no está bien definida y probada, puede que no  funcione correctamente, incluso si eventualmente se necesitara. 
	• A menos que existan especificaciones y algún tipo de control de revisión, la función no puede ser conocida por los programadores que podrían hacer uso de ella.
	• Cualquier nueva característica impone restricciones en lo que se puede hacer en el futuro, por lo que una característica innecesaria puede interrumpir características necesarias que se agreguen en el futuro.

▫ Debe ser utilizado en combinación con varias otras prácticas, tales como refactorización continua que implica la continua automatización de pruebas unitarias y la integración continua

## 🔹 ¿Qué significa YAGNI?

**YAGNI = "You Aren’t Gonna Need It"**  
(“No lo vas a necesitar”).

Es un **principio de desarrollo ágil** que dice:

> _“No implementes funcionalidad hasta que realmente sea necesaria.”_

---

## 🔹 ¿Por qué es importante?

Muchas veces los programadores agregamos código “por si acaso” o porque _“seguro lo van a pedir en el futuro”_.  
Eso genera:

- **Código muerto** o nunca usado.
    
- **Complejidad innecesaria**.
    
- Más **tiempo de mantenimiento y pruebas**.
    

👉 YAGNI nos recuerda que **solo debemos programar lo que hace falta ahora**, no lo que creemos que quizá haga falta mañana.

---

## 🧩 Ejemplo en Java

### ❌ Mal (violando YAGNI):

```java
public class Calculadora {
    public int sumar(int a, int b) {
        return a + b;
    }

    public int restar(int a, int b) {
        return a - b;
    }

    // "Por si acaso" algún día se necesita
    public int multiplicar(int a, int b) {
        return a * b;
    }

    public int dividir(int a, int b) {
        return a / b;
    }
}
```

👉 El cliente solo pidió **sumar y restar**, pero el programador agregó multiplicar y dividir “porque seguro lo van a usar después”.  
Ese código extra:

- Hay que **mantenerlo**.
    
- Puede tener **bugs innecesarios**.
    
- **Complica** sin aportar valor hoy.
    

---

### ✅ Bien (aplicando YAGNI):

```java
public class Calculadora {
    public int sumar(int a, int b) {
        return a + b;
    }

    public int restar(int a, int b) {
        return a - b;
    }
}
```

👉 Solo lo que se necesita ahora.  
Si mañana el cliente pide multiplicar → se implementa en ese momento, **con un requisito real**.

---

## 🎯 Resumen

- **YAGNI** = _“No lo vas a necesitar”_.
    
- Evita programar funcionalidades que no han sido pedidas.
    
- Reduce complejidad, tiempo de desarrollo y costo de mantenimiento.
    
- Muy relacionado con otros principios ágiles como **KISS** (_Keep It Simple, Stupid_) y **Lean Software Development**.
