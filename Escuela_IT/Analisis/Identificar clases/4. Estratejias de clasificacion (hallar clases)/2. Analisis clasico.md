### Estrategia: Análisis clásico

El **análisis clásico** es una de las estrategias más difundidas para
identificar clases y objetos. Parte de la idea de que las clases se
**derivan de las fuentes presentes en el dominio del problema**, es decir,
de los elementos que los requisitos describen de forma explícita.

Diversos metodólogos han propuesto distintas **fuentes de clases y
objetos**. La estrategia consiste en recorrer los requisitos y preguntarse,
para cada fuente, qué elementos del dominio encajan en ella.

#### Fuentes de clases y objetos

| Fuente | Descripción | Ejemplos |
| ------ | ----------- | -------- |
| **Cosas / objetos físicos** | Objetos tangibles o grupos de objetos que se pueden ver y tocar. | `Coche`, `SensorDePresión`, `DatosDeTelemetría` |
| **Conceptos** | Ideas o principios no tangibles que se usan para organizar o dar seguimiento a actividades y comunicaciones. | `Préstamo`, `Reunión`, `Intersección` |
| **Eventos** | Cosas que pasan, normalmente en una fecha determinada; suelen ocurrir *a* otro objeto. | `Aterrizaje`, `Interrupción`, `Solicitud` |
| **Personas** | Seres humanos que cumplen una función o juegan distintos roles frente a la aplicación. | `Madre`, `Profesor`, `Político` |
| **Organizaciones** | Colecciones formalmente organizadas de personas y recursos con una misión definida, cuya existencia es independiente de los individuos. | `Universidad`, `Banco`, `Aerolínea` |
| **Lugares físicos** | Oficinas y sitios importantes para la aplicación; zonas reservadas para personas o cosas. | `Aula`, `Bodega`, `SalaDeEspera` |
| **Dispositivos** | Artefactos con los que interactúa la aplicación. | `Impresora`, `LectorDeCódigo`, `Terminal` |
| **Sistemas externos** | Otros sistemas con los que la aplicación debe interactuar. | `PasarelaDePago`, `ServicioMeteorológico`, `SistemaDeNómina` |

#### Cómo aplicarla

1. Tomar un requisito o una frase del dominio.
2. Recorrer la lista de fuentes y marcar los elementos que aparecen.
3. Asignarles un nombre en el **vocabulario del dominio**.
4. Descartar los que sean atributos, operaciones o simples sinónimos.
5. Revisar que cada candidato tenga sentido como abstracción del sistema.

#### Ejemplo: sistema de biblioteca

> El **socio** presenta una **solicitud** de **préstamo** en la
> **biblioteca**. El **bibliotecario** usa el **lector de código** para
> **registrar** el **libro** y consulta el **sistema de inventario**.

| Fuente | Elemento del texto | Clase candidata |
| ------ | ------------------ | --------------- |
| Personas | socio, bibliotecario | `Socio`, `Bibliotecario` |
| Eventos | solicitud, préstamo | `Solicitud`, `Préstamo` |
| Organizaciones | biblioteca | `Biblioteca` |
| Dispositivos | lector de código | `LectorDeCódigo` |
| Sistemas externos | sistema de inventario | `SistemaDeInventario` |
| Cosas físicas | libro | `Libro` |
| Conceptos | (ninguno explícito) | — |

Observa que **registrar** es un **verbo**, por lo que se convierte en una
**operación** (`registrar()`), no en una clase. En cambio, **solicitud** y
**préstamo**, aunque describen acciones, se tratan como **eventos** con
identidad propia y, por tanto, sí son clases.

#### Ejemplo: sistema de peaje

| Fuente | Elemento | Clase candidata |
| ------ | -------- | --------------- |
| Cosas físicas | vehículo, caseta | `Vehículo`, `Caseta` |
| Dispositivos | cámara, barrera | `Cámara`, `Barrera` |
| Eventos | cruce, cobro | `Cruce`, `Cobro` |
| Conceptos | tarifa, saldo | `Tarifa`, `Saldo` |
| Personas | conductor, operador | `Conductor`, `Operador` |
| Organizaciones | concesionaria | `Concesionaria` |
| Sistemas externos | banco | `Banco` |

#### Ventajas

- Proporciona una **lista de partida amplia** y fácil de justificar.
- Es **sistemática**: no depende solo de la intuición del analista.
- Usa el **vocabulario del dominio**, lo que facilita la comunicación con
  los expertos.

#### Inconvenientes

- **No distingue** con claridad entre clases, atributos y operaciones; un
  mismo sustantivo puede ser cualquiera de los tres.
- Puede generar **clases innecesarias** o demasiado triviales.
- **No considera el comportamiento** ni las responsabilidades; para eso se
  usan estrategias complementarias (análisis del comportamiento, casos de
  uso).
- **No escala bien** por sí sola en dominios grandes y complejos.
