# 4. Bajo acoplamiento

> [!info] Principio **3 de 9** · [[1. GRASP|GRASP]]
> Anterior: [[3. Alta cohesion|Alta cohesión]] · Siguiente: [[5. Invension Pura|Invención pura]]

---

## ❓ Problema

*¿Cómo apoyar el bajo acoplamiento, el bajo impacto del cambio y el aumento de la reutilización?*

El **acoplamiento** mide la **fuerza** con que un elemento está conectado a, tiene conocimiento de, o **depende** de otros. Un elemento con **bajo acoplamiento** no depende de muchos otros.

El acoplamiento *alto* es indeseable porque:

- Cambios en clases relacionadas **obligan a cambios locales**.
- Es **más difícil de entender de forma aislada**.
- Es **más difícil de reutilizar** (necesita arrastrar las clases de las que depende).

---

## ✅ Solución

> [!success] Bajo acoplamiento
> Asignar responsabilidades de tal manera que el **acoplamiento se mantenga bajo**.

---

## 🔗 Formas de acoplamiento (de X a Y)

| Forma | Ejemplo |
|-------|---------|
| X tiene un **atributo** de tipo Y | `Venta` tiene un `Cliente` |
| X tiene un **método** que referencia Y (parámetro, variable local o retorno) | `calcular(Producto p)` |
| X **pide servicios** a un objeto Y | `venta.calcularTotal()` |
| X **hereda** (directa o indirectamente) de Y | `VentaContado extends Venta` |

> [!note] Acoplamiento indirecto
> X envía un mensaje a Z que devuelve objetos de Y: X queda acoplado a Y **a través de** Z.

---

## 💡 Ejemplo (tienda POS)

```java
// ❌ Alto acoplamiento: el controlador conoce la implementación concreta
class ControladorVenta {
  private VentaMySQLDAO dao = new VentaMySQLDAO(); // atado a MySQL
  void guardar(Venta v) { dao.insert(v); }
}
```

```java
// ✅ Bajo acoplamiento: depende de la abstracción
interface RepositorioVentas { void guardar(Venta v); }

class ControladorVenta {
  private RepositorioVentas repo;      // solo conoce la interfaz
  ControladorVenta(RepositorioVentas repo) { this.repo = repo; }
  void guardar(Venta v) { repo.guardar(v); }
}
```

Ahora cambiar de MySQL a PostgreSQL o a un stub de pruebas **no toca** `ControladorVenta`.

> [!tip] Regla práctica
> Depende de **interfaces** y de **clases estables**, no de implementaciones concretas ni de detalles volátiles.

---

## ⚠️ Matices importantes

- **No hay una medida absoluta** de "demasiado acoplamiento": depende del contexto.
- Un **grado moderado es normal y necesario**: sin colaboración entre objetos no hay sistema.
- El problema no es el acoplamiento *per se*, sino el acoplamiento a elementos **inestables** (interfaz, implementación o mera presencia cambiante).
- Acoplarse a lo **estable y generalizado** (p. ej. `java.util`) **rara vez es problema**.
- **Elige tus batallas:** reduce acoplamiento en los **puntos de cambio real**, no en todo por si acaso.

---

## ⚖️ Beneficios y contraindicaciones

| ✅ Beneficios | ⚠️ Contraindicaciones |
|---------------|------------------------|
| No se ve afectado por cambios de otros componentes | Acoplarse a **elementos estables** (bibliotecas estándar) es aceptable |
| Fácil de entender de forma aislada | Bajar acoplamiento **especulativamente** donde no hay cambio real desperdicia esfuerzo |
| Conveniente para **reutilizar** | |
| Menos dependencias de mantenimiento | |

---

## 🔗 Relación con otros patrones

- **Alta cohesión** suele **favorecer** el bajo acoplamiento.
- **Indirección** introduce un intermediario para **romper** un acoplamiento directo.
- **Variaciones protegidas** y **Polimorfismo** son mecanismos para **blindar** los puntos inestables.
- Se evalúa **junto** al Experto y la Cohesión; nunca en aislamiento.

---

## ✅ Conclusión para examen

1. **Acoplamiento** = fuerza de dependencia entre elementos.
2. **Bajo acoplamiento** → menos impacto del cambio, más comprensión y reutilización.
3. Se logra dependiendo de **interfaces/abstracciones** y de elementos **estables**.
4. Un grado **moderado es normal**; solo preocupa el acoplamiento a lo **inestable**.

> [!question] Pregunta típica
> *"¿Cómo aplicaría bajo acoplamiento entre la lógica de ventas y la base de datos?"*
> **Respuesta:** con una interfaz `RepositorioVentas`; el dominio depende de la interfaz y las implementaciones concretas (MySQL, PostgreSQL) se inyectan desde fuera.
