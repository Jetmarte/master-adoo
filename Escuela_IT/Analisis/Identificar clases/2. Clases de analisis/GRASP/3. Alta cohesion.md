# 3. Alta cohesión

> [!info] Principio **2 de 9** · [[1. GRASP|GRASP]]
> Anterior: [[2. Experto en la informacion|Experto en información]] · Siguiente: [[4. Bajo Acoplamiento|Bajo acoplamiento]]

---

## ❓ Problema

*¿Cómo mantener la complejidad manejable?*

La **cohesión** (funcional) mide **cuán fuerte y enfocadas** están las responsabilidades de un elemento (clase, subsistema…).

- **Alta cohesión:** responsabilidades muy relacionadas y **no hace una enorme cantidad de trabajo**.
- **Baja cohesión:** hace muchas cosas no relacionadas, o hace **demasiado**. Suele indicar un "grano muy grande" de abstracción o responsabilidades que **deberían delegarse**.

---

## ✅ Solución

> [!success] Alta cohesión
> Asignar una responsabilidad **de modo que la cohesión siga siendo alta**: pocas responsabilidades, bien relacionadas, y **colaborar** con otros objetos cuando la tarea es grande.

---

## 📊 Grados de cohesión

| Grado | Descripción | Ejemplo POS |
|-------|-------------|-------------|
| **Muy baja** | Una clase responsable de muchas áreas funcionales distintas | `GestorTodo`: login + ventas + PDFs + base de datos |
| **Baja** | Una responsabilidad, pero una tarea compleja dentro de un área | `Venta` que además calcula impuestos, imprime ticket y guarda en BD |
| **Moderada** | Responsabilidades ligeras en varias áreas lógicamente relacionadas | `Venta` que calcula total y descuentos (relacionado) |
| **Alta** | Responsabilidades moderadas en **un área** y colabora con otras clases | `Venta` solo gestiona líneas y totales; delega persistencia e impresión |

---

## 💡 Ejemplo (tienda POS)

```java
// ✅ Cohesiva: solo sabe de la venta
class Venta {
  private List<LineaVenta> lineas = new ArrayList<>();
  void agregar(LineaVenta l) { lineas.add(l); }
  double total() { return lineas.stream().mapToDouble(LineaVenta::subtotal).sum(); }
}

// ✅ Cada clase con su responsabilidad
class RepositorioVentas { void guardar(Venta v) { /* persistencia */ } }
class ImpresoraTicket  { void imprimir(Venta v) { /* formato ticket  */ } }
```

```java
// ❌ Baja cohesión: Venta hace de todo
class Venta {
  double total() { ... }
  void guardarEnMySQL() { ... }     // persistencia
  void imprimirTicket() { ... }     // presentación
  void enviarEmailCliente() { ... } // comunicación
}
```

> [!tip] Analogía del mundo real
> Si una persona asume demasiadas responsabilidades no relacionadas —sobre todo las que deberían delegar— **no es eficaz**. Igual una clase.

> [!note] Ejemplo clásico de cohesión
> `Fecha` debe tener solo lo suyo: `dia`, `mes`, `anio` y operaciones como `esBisiesto()` o `sumarDias()`. No debería imprimir facturas ni conectarse a la BD.

---

## ⚖️ Beneficios y contraindicaciones

| ✅ Beneficios | ⚠️ Contraindicaciones (menor cohesión justificada) |
|---------------|-----------------------------------------------------|
| Aumenta **claridad** y comprensión del diseño | **Clases de utilidad** agrupan funciones por comodidad (empeora el mantenimiento si se abusa) |
| Simplifica **mantenimiento y mejoras** | **Objetos servidores distribuidos**: conviene juntar operaciones remotas para reducir llamadas de red |
| Suele ser **compatible con bajo acoplamiento** | |
| Grano fino → mayor **reutilización** | |

---

## 🔗 Relación con otros patrones

- **Bajo acoplamiento** y alta cohesión son **objetivos gemelos**; normalmente uno ayuda al otro.
- **Experto en información** puede *bajar* la cohesión si una clase acumula datos de varios temas.
- **Invención pura** sirve para **mover** lógica que rompe la cohesión de una entidad del dominio.

---

## ✅ Conclusión para examen

1. **Cohesión** = grado en que las responsabilidades de una clase están **relacionadas y enfocadas**.
2. **Alta cohesión** = pocas responsabilidades, muy relacionadas, sin exceso de trabajo.
3. Mejora **comprensión, mantenimiento y reutilización**.
4. Es un **objetivo a evaluar continuamente** en cada decisión de diseño.

> [!question] Pregunta típica
> *"¿Qué es la alta cohesión y cómo se logra?"*
> **Respuesta:** que una clase tenga responsabilidades afines y no haga demasiado; se logra asignando una responsabilidad por área y **delegando** el resto (persistencia, impresión, etc.) a otras clases.
