# 8. Indirección

> [!info] Principio **7 de 9** · [[1. GRASP|GRASP]]
> Anterior: [[7. Creador|Creador]] · Siguiente: [[9. Polimorfismo|Polimorfismo]]

---

## ❓ Problema

*¿Dónde asignar una responsabilidad para **evitar el acoplamiento directo** entre dos o más cosas?*

*¿Cómo desacoplar objetos para fomentar el **bajo acoplamiento** y mantener alto el potencial de **reutilización**?*

---

## ✅ Solución

> [!success] Indirección
> Asignar la responsabilidad a un **componente intermedio** que **medie** entre otros componentes o servicios, para que **no se acoplen directamente**. El intermediario crea una **indirección** entre ellos.

```
   Sin indirección:        A ──────────► B     (acoplados)

   Con indirección:        A ────► M ────► B    (A solo conoce a M)
```

> [!quote] Dennis DeBruler
> "La mayoría de los problemas en las Ciencias de la Computación pueden resolverse **añadiendo otro nivel de indirección**."
> "La mayoría de los problemas de **rendimiento** pueden resolverse **eliminando** otro nivel de indirección."

---

## 💡 Ejemplo (tienda POS)

Sin indirección, `Venta` conoce la API concreta de email:

```java
// ❌ Venta acoplada al proveedor de email
class Venta {
  void finalizar() {
    EmailAPI api = new EmailAPI();     // acoplamiento directo
    api.enviar("compra realizada");
  }
}
```

Con indirección, un **servicio intermedio** media:

```java
// ✅ Intermediario
interface ServicioNotificaciones { void enviarConfirmacion(Venta v); }

class NotificadorEmail implements ServicioNotificaciones {
  private EmailAPI api;                 // el proveedor queda oculto
  public void enviarConfirmacion(Venta v) { api.enviar("Compra " + v.id()); }
}

class Venta {
  private ServicioNotificaciones notificador;   // solo conoce la abstracción
  void finalizar() { notificador.enviarConfirmacion(this); }
}
```

> [!note] Otros intermediarios típicos
> `RepositorioVentas` media entre el dominio y la BD. `ControladorVenta` media entre la UI y el dominio. Un *broker* o una máquina virtual son indirecciones complejas.

---

## 💡 Para qué sirve (implicaciones)

| Uso | Explicación |
|-----|-------------|
| **Compartir lógica** | Un submétodo usado en dos sitios, o un método en una clase base compartida |
| **Explicar la intención** | Nombrar bien clases y métodos comunica el "qué"; el interior explica el "cómo" |
| **Aislar cambios** | Si algo se comparte y hay que cambiarlo en un solo caso, se hace una subclase y se referencia solo ahí |
| **Codificar lógica condicional** | El **paso de mensajes polimórficos** expresa condicionales de forma flexible y clara |

---

## ⚠️ Contraindicaciones

> [!warning] Indirecciones parasitarias
> Si encuentras métodos creados para un propósito que nunca se usó, o un componente que se esperaba compartir/polimórfico y **solo se usa en un sitio**… son **indirecciones parasitarias**. **Quítalas.**

- No añadas indirección "por si acaso": solo si hay un **cambio realista** o una necesidad de desacople concreta.
- Cada nivel de indirección **añade complejidad** (y a veces coste de rendimiento).

---

## ⚖️ Beneficios y contraindicaciones

| ✅ Beneficios | ⚠️ Contraindicaciones |
|---------------|------------------------|
| **Bajo acoplamiento** entre componentes | Indirección **innecesaria** = complejidad extra |
| Mayor **reutilización** y flexibilidad | Puede **degradar rendimiento** (capas extra) |
| Permite **sustituir** un componente sin afectar al cliente | Difícil de justificar si solo hay **un** uso |

---

## 🔗 Relación con otros patrones

- **Bajo acoplamiento**: la indirección es un **mecanismo** para lograrlo.
- **Variaciones protegidas**: el intermediario suele ser una **interfaz estable** ante cambios.
- **Polimorfismo**: el intermediario aprovecha mensajes polimórficos para variar comportamiento.
- **Invención pura**: muchos intermediarios (servicios, repositorios) son clases artificiales.

---

## ✅ Conclusión para examen

1. **Indirección** = poner un **intermediario** para que dos componentes no se acoplen directamente.
2. Apoya **bajo acoplamiento**, **reutilización** y **sustituibilidad**.
3. Mecanismos: interfaces, servicios, repositorios, brokers.
4. **Cuidado** con las indirecciones parasitarias: si no aportan, se eliminan.

> [!question] Pregunta típica
> *"¿Cómo desacoplaría `Venta` del envío de emails?"*
> **Respuesta:** con una indirección: `interface ServicioNotificaciones` y una implementación `NotificadorEmail`; `Venta` solo depende de la interfaz.
