## 📖 Definición

> [!quote] Grady Booch
> "Todas las entidades que tienen una determinada propiedad o conjunto de propiedades en común forman una categoría. Estas propiedades son **necesarias y suficientes** para definir la categoría."

Es el enfoque heredado de **Aristóteles**: una categoría se define por una lista **cerrada** de atributos.

| Concepto | Significado | Consecuencia |
|----------|-------------|--------------|
| **Necesarias** | Todo miembro *tiene* que tenerlas | Si le falta una → **no pertenece** |
| **Suficientes** | Si las tiene todas, pertenece | No hace falta nada más |

**Ejemplo formal perfecto:** `Triángulo` = figura plana cerrada con 3 lados.
Todo triángulo cumple eso, y todo lo que cumple eso es un triángulo.

---

## 🔧 Aplicación al análisis orientado a objetos

El procedimiento es:

1. Observar un conjunto de objetos/entidades del dominio.
2. Detectar **atributos y métodos compartidos**.
3. Definir una **clase** como ese conjunto común.

```java
class Ave {
  // atributos comunes
  pico, plumas, alas, patas;
  // métodos comunes
  volar(), ponerHuevos(), comer();
}
```

Si algo tiene `pico + plumas + alas` y `vuela + poneHuevos` → es un `Ave`.

> [!tip] Por qué importa
> Es la base intuitiva de la **generalización / herencia** y lo primero que intentamos al identificar clases. **Funciona la mayoría de las veces.**

## ⚠️ Crítica: las categorías naturales son incómodas

> [!warning] Bart Kosko
> "Las categorías naturales tienden a ser un poco incómodas: la mayoría de los pájaros vuelan, pero algunos no lo hacen; las sillas pueden consistir en madera, plástico o metal y pueden tener casi cualquier número de patas... Parece prácticamente imposible llegar a una lista de propiedades para cualquier categoría natural que excluya a todos los ejemplos que no están en la categoría e incluya todos los ejemplos que se encuentran en la categoría."

### 1. Excepciones que rompen la regla

- `Pingüino` tiene pico, plumas y alas... pero **no vuela**.
- `Avestruz`, `kiwi`, `pato doméstico` → tampoco encajan en `volar()`.
- Si `volar()` fuera necesario y suficiente, el pingüino **dejaría de ser ave**, lo cual es absurdo.

### 2. Variabilidad infinita

- `Silla`: ¿4 patas? ¿madera? Hay sillas de 1, 3 o 5 patas, de plástico, metal, sin respaldo, de diseño...
- No existe una lista de propiedades que incluya *todas* las sillas y excluya *todo* lo que no es silla.

---

## 🧩 Cómo resolverlo en OO

El error es poner en la clase base algo que **no es común a todos los miembros**. Si aparece una excepción, no fuerces la herencia:

- Subir `volar()` a una **interfaz** `Volador`.
- Dejar `Ave` solo con lo verdaderamente común.
- Usar **composición** cuando la relación no sea "es-un".

```java
class Ave { pico, plumas; }                 // común a todas las aves
interface Volador { void volar(); }
interface Nadador { void nadar(); }

class Aguila extends Ave implements Volador { ... }
class Pinguino extends Ave implements Nadador { ... }
```

> [!danger] Anti-patrón
> `Pinguino extends Ave` anulando `volar()` **viola el Principio de Sustitución de Liskov**.

---

## ✅ Ventajas vs ❌ Límites

| ✅ Ventajas | ❌ Límites |
|-------------|------------|
| Simple, riguroso y verificable | Frágil ante excepciones del mundo real |
| Ideal para dominios formales: matemáticas, facturas, cuentas, `Fecha`, `DNI`, `Pedido` | Tiende a crear jerarquías rígidas que luego hay que refactorizar |
| Se traduce directo a clase UML/Java: atributos + operaciones | No maneja conceptos difusos, subjetivos o evolutivos |
| Facilita validación: `if cumple(propiedades) → instancia válida` | No admite gradualidad (pertenece o no pertenece) |

## ✅ Conclusión para examen

1. Categorización clásica = **propiedades necesarias y suficientes** [Booch / Aristóteles].
2. Es la base del modelado OO y **funciona la mayoría de las veces**.
3. Falla en **categorías naturales**: el pingüino no vuela, la silla no tiene forma única [Kosko].
4. En diseño: si aparece una excepción, **no fuerces la herencia** → revisa la abstracción y usa interfaces / composición.

> *"Ponga un ejemplo donde falle la categorización clásica y cómo lo resolvería en OO."*
> **Respuesta:** `Ave - Pingüino`; solución con `interface Volador` + `class Ave { pico, plumas }` + `class Pinguino extends Ave implements Nadador`.
