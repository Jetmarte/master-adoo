# 4. Relación de asociación

> [!info] Relación **cliente–servidor estable** · Sección 4.4.4
> Anterior: [[3. Relacion de composicion - agregacion|Composición y agregación]] · Siguiente: [[5. Relacion de dependencia (uso)|Dependencia (uso)]]

---

## 📖 Definición

La **asociación** es la relación que **perdura** entre un **cliente** y un **servidor determinado**.

> [!tip] Regla de detección
> Existe una relación de asociación entre la clase **A** (cliente) y la clase **B** (servidor) si un objeto de A **disfruta de los servicios de un objeto determinado de B** (le lanza mensajes) para cumplir su responsabilidad **en diversos momentos**, creándose una **dependencia del objeto servidor**.

Palabras clave:

| Concepto | Significado |
|----------|-------------|
| **Cliente** | Objeto que pide el servicio |
| **Servidor** | Objeto concreto que presta el servicio |
| **Perdurable** | La colaboración se repite en el tiempo |
| **Determinado** | No sirve cualquier servidor: se usa **ese** |

No se limita a cuestiones **tangibles** (procesador –cliente– y memoria –servidor–); también cubre relaciones **lógicas**:

| Expresión | Ejemplo (cliente – servidor) |
|-----------|------------------------------|
| "provecho" | `Socio` – `Club` |
| "beneficio" | `Empresa` – `Banca` |
| "pertenencia" | `Socio` – `Biblioteca` |
| "consulta" | `Cliente` – `Banco` |

---

## 🧭 Características

| Característica | Valor |
|----------------|-------|
| **Visibilidad** | Pública |
| **Temporalidad** | No momentánea |
| **Versatilidad** | Reducida |

> [!note] Por qué versatilidad reducida
> El cliente está atado a un **servidor determinado** (su banco, su biblioteca, su procesador). No le sirve cualquier objeto de la clase servidor.

---

## 💻 Implementación en Java

El cliente mantiene una **referencia como atributo** al servidor, suministrada desde un **constructor** o un **método** para establecer la asociación.

```java
class Socio {
    private final Biblioteca biblioteca; // servidor concreto y estable

    Socio(Biblioteca biblioteca) {
        this.biblioteca = biblioteca;
    }

    void solicitarPrestamo(Libro libro) {
        biblioteca.prestar(libro, this);
    }
}
```

La asociación también puede ser **bidireccional**:

```java
class Biblioteca {
    private final List<Socio> socios = new ArrayList<>();

    void registrar(Socio socio) {
        socios.add(socio);
    }
}
```

## 🆚 Asociación vs. dependencia (uso)

| Criterio | Asociación | Dependencia (uso) |
|----------|------------|-------------------|
| **Duración** | No momentánea (perdura) | **Momentánea** |
| **Servidor** | **Determinado** | **Cualquiera** |
| **Dependencia futura** | Sí | **No** |
| **En código** | Referencia como **atributo** | **Parámetro**, retorno o variable local |
| **UML** | Línea continua | Flecha discontinua |

---

## 🆚 Asociación vs. agregación

- Ambas son **públicas**, **no momentáneas** y de **versatilidad reducida**.
- La diferencia es semántica: en la **agregación** hay una relación **todo–parte**; en la **asociación**, no.

> [!example] Para no confundirlas
> - `Biblioteca` ◇— `Libro` → **agregación**: el libro *forma parte* de la biblioteca.
> - `Socio` — `Biblioteca` → **asociación**: el socio *usa* la biblioteca, pero no es una parte suya.

---

## 📐 Notación UML

```text
Socio ──────────── Biblioteca        (asociación)
Socio ───────────► Biblioteca        (asociación navegable)
```

- Línea **continua** entre las clases.
- Se puede añadir **multiplicidad** en los extremos (`1`, `0..*`, `1..*`) y un **rol**.
- La flecha indica **navegabilidad** (quién conoce a quién).

---

## ✅ Conclusión para examen

1. Asociación = colaboración **duradera** entre un cliente y un **servidor determinado**.
2. Visibilidad **pública**, temporalidad **no momentánea**, versatilidad **reducida**.
3. Se implementa como una **referencia atributo** al servidor, recibida por constructor o setter.
4. Se distingue de la **dependencia** por su duración y del **todo–parte** por su semántica.
