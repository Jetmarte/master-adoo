## 📊 Flujo de Datos Detallado

### Request/Response Cycle

```
1. USUARIO INTERACCIÓN
   └─ Click en botón, cambio en input, etc.

2. COMPONENTE REACT
   └─ DraftLeadForm, DraftList, etc.

3. HOOK (useDraft)
   ├─ State Management (useState)
   ├─ Error Handling (error state)
   └─ Loading State (loading flag)

4. SERVICIO (draftService)
   ├─ Business Logic
   ├─ Data Transformation
   └─ Validation

5. API CLIENT (apiClient)
   ├─ Prepare Request
   ├─ Add Headers (auth, content-type)
   ├─ Handle Interceptors
   └─ HTTP Method (GET, POST, PUT, DELETE)

6. HTTP REQUEST
   └─ Network call to backend

7. BACKEND HANDLER
   ├─ Authentication Check
   ├─ Authorization Check
   ├─ Input Validation
   ├─ Business Logic
   ├─ Database Operation
   └─ Response Preparation

8. HTTP RESPONSE
   ├─ Status Code (200, 201, 400, 401, etc.)
   └─ JSON Payload

9. API CLIENT
   ├─ Check Status Code
   ├─ Parse JSON
   ├─ Handle Errors
   └─ Transform Response

10. SERVICIO
    ├─ Process Data
    └─ Return to Hook

11. HOOK
    ├─ Update State
    └─ Trigger Re-render

12. COMPONENTE
    ├─ Re-render with new data
    └─ Display to User

13. USUARIO VE RESULTADO
```

│  }
│

│

│
├─ error: null
│
└─ Estados de Transición:
   ├─ INICIAL (form vacío)
   ├─ EDITANDO (usuario escribiendo)
   ├─ VALIDANDO (llamadas a API para validar)
   ├─ GUARDANDO (PUT request en progreso)
   ├─ ÉXITO (guardado con éxito)
   ├─ ERROR (error en la operación)
   └─ CONFIRMANDO (POST para confirmar)
```

## 🌐 Endpoints Mapeados

### Create Draft
```
REQUEST:
POST /api/drafts
Headers: {
  Authorization: "Bearer token",
  Content-Type: "application/json"
}
Body: {
  nombre: "Carlos López",
  email: "carlos@empresa.com",
  empresa: "TechCorp"
}

BACKEND PROCESS:
1. Validate token ✅
2. Extract userId from token
3. Validate input (required fields)
4. Check email format
5. Check for duplicates
6. Create document in DB
7. Return created draft

RESPONSE:
{
  success: true,
  data: { ... draft object ... }
}
```

### List Drafts
```
REQUEST:
GET /api/drafts?page=1&pageSize=20&filter=incompletos&sortBy=-updatedAt
Headers: { Authorization: "Bearer token" }

BACKEND PROCESS:
1. Validate token
2. Parse query params
3. Build database query
4. Apply filters (estado = 'draft')
5. Apply sorting
6. Apply pagination
7. Count total
8. Return paginated results

RESPONSE:
{
  success: true,
  data: {
    items: [ ... ],
    total: 150,
    page: 1,
    pageSize: 20,
    totalPages: 8
  }
}
```

### Update Draft
```
REQUEST:
PUT /api/drafts/{draftId}
Headers: { Authorization: "Bearer token" }
Body: {
  telefono: "+34 912345678",
  cargo: "Director TI"
}

BACKEND PROCESS:
1. Validate token
2. Check authorization (owner or admin)
3. Fetch existing draft
4. Merge with new data
5. Validate all fields
6. Check for duplicates
7. Calculate completeness
8. Update in DB
9. Return updated draft

RESPONSE:
{
  success: true,
  data: { ... updated draft ... }
}
```

### Confirm Draft
```
REQUEST:
POST /api/drafts/{draftId}/confirm
Headers: { Authorization: "Bearer token" }
Body: {
  vendedorAsignado: "USR-456",
  fuente: "LinkedIn"
}

BACKEND PROCESS:
1. Validate token
2. Fetch draft
3. Validate completeness >= 100%
4. Check for duplicates
5. Validate all required fields
6. Update estado: 'draft' → 'activo'
7. Assign vendor
8. Record source
9. Create audit log
10. Update in DB
11. Return activated lead

RESPONSE:
{
  success: true,
  data: { ... activated lead ... },
  message: "Lead convertido a estado ACTIVO"
}
```

```

├─ CREADOR: ✅ Puede ver su propio draft

### Tipos de Errores Comunes

```
400 Bad Request
├─ Email formato inválido
├─ Teléfono formato inválido
├─ Campos requeridos faltantes
└─ Datos malformados

401 Unauthorized
├─ Token no proporcionado
├─ Token expirado
├─ Token inválido
└─ Firma incorrecta

403 Forbidden
├─ No es propietario del draft
├─ No tiene permisos para confirmar
└─ Usuario deshabilitado

404 Not Found
├─ Draft no existe
├─ Vendedor no existe
└─ Recurso eliminado

409 Conflict
├─ Email duplicado
├─ Teléfono duplicado
└─ Lead ya existe

500 Internal Server Error
├─ Error en base de datos
├─ Error en servidor
└─ Error no previsto
```

## 📋 Resumen de Capas

| Capa | Responsabilidad | Tecnología |
|------|-----------------|-----------|
| **UI** | Renderizar, interacción | React, TSX |
| **Hooks** | State management local | React Hooks |
| **Services** | Lógica de negocio | TypeScript |
| **API Client** | HTTP communication | Axios |
| **Backend** | Procesar requests | Express, Node.js |
| **Database** | Almacenar datos | MongoDB/PostgreSQL |

Cada capa es **independiente**, **testeable** y **reutilizable**.
